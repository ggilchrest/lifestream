01

Setup

Start an isolated review

Open a terminal in the Lifestream checkout. The launcher uses the existing ai5090 development providers and creates an empty review database, separate from your normal data.

node scripts/start-relationship-review.mjs

Open the Review app URL printed in the terminal (normally 127.0.0.1:43181/control/). Keep the terminal open. Save the printed review-directory path for the restart step. If the providers are unavailable, resolve that access first; the launcher does not substitute a fixture.

Read the installer-token.txt file at the printed path locally. Enter an account name, a new password of at least 12 characters, and that token under Local sign-in. Choose Enroll first Owner. Save the recovery codes privately; never paste tokens, passwords or codes into this guide.

What to check

You reach authenticated administration. The review directory is new, and no existing personal records appear.

Compare, reject and promote a reversible variant
Use two source families and two repeats. This produces 12 comparison outputs per experiment: two representations × three variants × two repeats. The held-out phase adds 12 separate outputs.
  1. Refresh Lab. Confirm it names the selected real development provider. Set comparison prompt Give a concrete Python example., family synthetic-comparison, and held-out prompt Explain a cache in one short sentence., family synthetic-held-out. Choose convention-oriented candidate representation and two repeats.
  2. Confirm synthetic input and transmission to the displayed provider. Prepare Lab, then Run comparison. Wait for 12 completed results. Review both representations and unpersonalized/current/candidate outputs. An unpersonalized Python reply should not contain your saved identifier.
  3. Reject Lab Candidate. Verify the prior active configuration remains active and the rejected experiment is preserved.
  4. Prepare a new experiment with the same explicit consent. Run its comparison, then Evaluate Held-Out Scenarios. Review the separate 12 held-out results. Do not treat a model score as your judgment of fit.
  5. Promote for normal review only after both phases complete. Inspect the resulting inactive configuration, preview and activate it through settings, then prepare and activate a rollback to your earlier configuration.
If any request fails, the phase is not a pass. Preserve the partial/failure state and notes. Use the pinned resume control only when available and still valid; do not change model or time budgets to force a pass.
What to check
36 outputs complete across the rejected comparison and the promoted comparison plus held-out phase. Rejection, explicit promotion, activation and rollback behave as separate steps. You can judge whether the comparison is useful.

Six privacy actions, six different effects
ActionMeaning in this review
Stop CollectionCloses collection and extraction. Retained records and completed candidate review remain.
Revoke ProcessingWithholds selected records and dependent processing. Retains source payload for administration.
Stop PersonalizationKeeps the source but withholds it from ordinary inference. Training consent stays separate.
Prohibit TrainingPrevents new training use and quarantines dependent artifacts. Ordinary personalization stays unchanged.
Delete SourceRemoves selected source payload/copies. Dependent records are withheld; derived payload can remain.
Forget Derived InformationRemoves selected source and derived payloads, cancels affected work, invalidates views and quarantines artifacts.

Check audience changes and forget selected sources
  1. Set Session disclosure to Unknown / shared and apply. The inspection clears. Run the Python question: private declarations and identifiers should be absent from the supplied context and reply. Restore your authenticated-session disclosure explicitly.
  2. Start a longer ordinary request, then use Cancel Request. The result must be labeled cancelled, not completed. Start another request and change disclosure while it is pending; stale inspection content should clear. Restore your disclosure afterward.
  3. In Source Use and Forgetting, read the six actions below before applying one. To remove the imported preference and its correction, select both the superseded original and corrected record. Do not select your separate User Profile unless you also want to forget it.
  4. Choose Forget Derived Information, then Preview Affected Sources. Review all listed record IDs and source copies. Apply only that reviewed operation.
  5. Read the per-artifact receipt: removed, withheld, quarantined and retry-required are different outcomes. If partial, use Retry Recorded Cleanup. Refresh records, insights and Lab; old dependent results must not remain eligible for use or promotion.
  6. Run the Python question again. Neither saved project identifier should remain in the supplied context or reply. The separately approved plain-language convention can remain.
What to check
The action affects the selected sources and their listed dependents. You can tell what was removed and what needs retry. Forgotten content does not return to current conversation.
