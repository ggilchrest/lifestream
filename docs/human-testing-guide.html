1

Open an isolated review

Start from a clean review directory so your notes cannot mix with another session.

Do this

  1. In the public checkout, run node scripts/start-relationship-review.mjs.
  2. Open the printed control-room URL. If it uses the default port, use Open sign in.
  3. Keep this guide open in another tab. Do not use a production URL.

Look for

A review-directory or installer-token notice, a clear session header, and distinct areas for records, settings, insights, Lab, and privacy.

Expected: the control plane loads without borrowing an earlier review’s state.
If the page is unavailable: record “environment unavailable,” stop this review, and do not silently switch providers. If the launcher prints Required provider status: inference=unavailable (inference health probe timed out), the ai5090 inference endpoint is the failed dependency. On the Windows development host, run the documented Enter-VoiceAIMode.ps1 recovery and wait for its bounded readiness result before retrying. Do not substitute a fixture or a different provider.
2

Set the session and Assistant profile

Establish who the session is for before entering the synthetic note.

Click path

  1. Open Assistant profile and create or select Review Assistant.
  2. Open Session disclosure.
  3. Under Audience, choose My authenticated session — allow approved context.
  4. Click Apply Session Disclosure. Wait for the message Approved context allowed in this authenticated session.
  5. Then continue to Import & review. That is where you enter the supplied synthetic note in step 3.

What you are setting

Audience answers one simple question: “Who may this session use approved private context for?” Choose your signed-in review session. This is a session privacy choice, not a person-detection or microphone setting.

Expected: the session page shows Approved context allowed in this authenticated session and a revision number.
There is no separate “send scoped context” button. The old wording meant “finish the audience setting before you import or send the synthetic test content.” Do not look for another transmission control here.
Do not choose “Unknown / shared.” That option intentionally withholds private context and will make later memory steps appear empty. It is correct for a shared or unidentified audience, but not for this authenticated synthetic review.
3

Import the literal synthetic memory test

Use one supplied text file so you do not have to retype or remember the test token.

Open Import & reviewOpen RecordsDownload the one-line test file

Use this file

Download synthetic-memory-token.txt from this guide. It contains exactly one line:

SYNPRJ_Q7M4

Do not add a second note. The token is an arbitrary case-sensitive string, not a project, person, or object.

Exact click path

  1. Open Import & review.
  2. Leave Declared Format as UTF-8 Notes v1 and Source Author as Unknown / Observation.
  3. Choose synthetic-memory-token.txt under Selected Files.
  4. Check These files concern me and are mine to import; excluded third-party records and credentials are absent.
  5. Click Inventory Selection.
  6. Choose the new inventoried job in Saved Import Job.
  7. Click Collect Pinned Snapshot, then click Extract Candidates.
  8. When the candidate appears, select its checkbox, click Approve Selected, select the candidate checkbox again, then click Admit Approved Selection.
  9. Open Records and click Refresh Records. The approved row should show SYNPRJ_Q7M4.
If Records already contains SYNPRJ_Q7M4 in this review, do not import it again. Use the existing row and continue with the conversation test. Importing again creates a second synthetic record and makes the later results harder to read.
Record the exact reply: open Conversation, enter Give a concrete Python example., and send it. Capture the full reply, including capitalization, omission, or no reply. An incorrect case, missing token, or missing reply is model-quality telemetry; continue the application review unless the application itself crashes, loses the record, or violates the session boundary.
4

Review records, correction, annotation, and pinning

Check that the controls are understandable and that each action leaves a visible record.

Open Records

Do this in the record row

  1. Open Details & actions for the synthetic note.
  2. Choose Annotate, enter Synthetic review note., then choose Apply Reviewed Operation.
  3. Choose Pin and confirm the row visibly changes.
  4. Use the correction control once, then inspect the history or receipt.

Two terms that are easy to miss

Annotate adds review commentary. It does not rewrite the source memory. Pin marks salience for the review view. It does not mean “true,” “permanent,” or “approved.”

Expected: the row shows a friendly content label first. Open its details only when you need the identifier, revision, or receipt.
5

Prepare, preview, activate, and roll back a draft

Follow the visible draft lifecycle; never infer activation from a preview alone.

Open Settings & replies

Do this

  1. Choose the earlier configuration and select Prepare Selected Rollback.
  2. Choose Preview Selected Draft.
  3. Read the preview, then click Activate Reviewed Draft directly below it.
  4. Confirm the active version and exercise the rollback or restore control if shown.

What activation means

Preview only renders a candidate. Activation changes the current reviewed configuration. The active version, revision, and resulting state should be visible after the click.

Expected: the sequence is discoverable, the active state is unambiguous, and a rollback leaves a receipt rather than silently replacing history.
If a button appears out of order: scroll back to the draft panel after preview. The activation action is below the preview result, not in the unrelated page footer.
6

Run and read the insight lenses

Read the result as a structured discussion, not as an unquestionable conclusion.

Open Insights & feedback

Do this

  1. In Insights & feedback, click Run insight lenses.
  2. Open each named lens or perspective card after the run completes.
  3. Read support, counterevidence, uncertainty, proposed interventions, and the lens conclusion where present.

If you see no “lenses” table

Results appear as named perspective cards or expandable rows rather than a table literally titled “lenses.” Look immediately below the run status and open each named result.

Expected: every perspective is attributable to this run, and uncertainty is visible instead of hidden behind one confidence number.
7

Compare in Lab and inspect safe rejection

Use the protected synthetic comparison to check that selection and rejection are legible.

Open Relationship Lab

Do this

  1. Open the Lab comparison and select the supplied synthetic event set.
  2. Run the comparison across available variants or representations.
  3. Inspect the result and held-out or protected result when shown.
  4. Try rollback/restore and read its receipt.

What is in scope

This is a synthetic selection and evidence workflow. It does not prove physical audibility, warmth, production performance, or quality on personal data.

Expected: selected settings are explicit, rejected or oversized output is explained, and the system remains usable after a safe rejection.
Do not promote a Lab result into a provider claim. The selected-provider analysis contains two accepted synthetic samples and one safely rejected oversized sample. Record what you see; do not convert it into Human or production certification.
8

Check privacy, forgetting, and restart

Confirm that the review can end cleanly and a new session does not inherit old state.

Open Privacy & recoveryOpen Session disclosureOpen Account & access

Do this

  1. Read the current audience and disclosure state in Session disclosure.
  2. Use forgetting/removal in Privacy & recovery for the synthetic record, then inspect its receipt/history.
  3. End the session and restart the launcher with a new isolated directory.
  4. Check that the old token, annotation, pin, and draft are not silently presented as new-session state.

Expected boundary

Forgetting is a recorded operation, not just a row disappearing. A restart should make the isolation boundary visible.

Expected: the new session starts empty or with only declared synthetic fixtures, and audience must be established again before scoped transmission.
9

Inspect output readiness without over-claiming it

Review the boundary between Lifestream and a physical output device.

Open ReadinessOpen Conversation

Do this

  1. Open Readiness for the current session and modality.
  2. Confirm the readiness result names the session, modality, and delivery state.
  3. Use Conversation only when you need to inspect the session’s output controls.
  4. Record whether the UI distinguishes “accepted for delivery,” “played,” and “physically heard.”

Boundary to record

S083 readiness is a browser capability acknowledgment for one session and modality. It is not proof of physical presence, audibility, generated wording, retained PCM, or Human warmth.

Expected: the UI states what was accepted and leaves physical/perceptual claims for a separate Human observation.

Make the Human acceptance decision

Use your notes. A model-quality variance can remain a separate tracked note while you judge the product workflow.

Before choosing

Disposition

“Accepted with exclusions” is appropriate when the interface is acceptable but a separate model-quality, environment, physical, or perceptual limitation remains recorded.

Exporting is evidence handoff, not acceptance mutation. The downloaded JSON is a human review packet. It does not update the repository checkpoint or mark Human acceptance complete automatically.
