# Appearance packages and animation previews

An appearance changes presentation independently of Assistant identity, memory and voice. Packages remain separately supplied through the authenticated, digest-checked resource catalog. They contain bounded data and declared assets, never scripts or remote resource URLs.

In **Conversation**, select an **Appearance** and **Apply to** scope, then click **Apply appearance** between turns. A failed replacement retains the current display. **Restart display** recovers a failed renderer without replaying speech.

A **This session only** choice overrides **This endpoint**. Saving a new endpoint default keeps the current session override; the status identifies both selections. Click **Use endpoint default** between turns to remove the session override. The default is checked and loaded before the override is cleared. If it is unavailable or invalid, the current appearance and override remain.

Saved choices pin the package digest. Refreshing or reopening the page never adopts changed package bytes merely because the package ID is the same. A changed or missing package reports the limitation and retains the loaded display (or the neutral reference on a fresh page). Select and apply an available appearance explicitly to accept its current revision. This does not change the Assistant identity, voice, memory or other endpoints.

Expand **Preview animations** to inspect the applied appearance. Select an **Animation state** and click **Preview animation**. The preview lasts five seconds; **End preview** returns to the conversation immediately. Starting a real turn, changing the audience, leaving the page or replacing the appearance ends the preview. Preview does not save a selection, alter the Assistant, write memory or synthesize speech. **Speaking motion only** is a visual animation preview, not an audible-speaking claim or a lip-sync test.

The status distinguishes a declared animation, an idle fallback and an absent mapping. Select a **Face motion** and click **Preview face motion** for a five-second blink, left, right, up, down or centered-gaze preview. **End preview** ends either kind of preview. An appearance without the selected mapping explains that limitation. These controls do not supply phoneme alignment. Human inspection remains required for convincing motion, transitions and appearance quality.

Package schema `1.0.0` retains its existing `idle`, `listening`, `speaking` and `mouthAmplitude` animation mappings. Schema `1.1.0` additionally supports `preparing`, `interrupted`, `working`, `waiting` and `failure`, with optional `transitionSeconds` from 0 to 1; the default is 0.15 seconds. Each mapping must name exactly one clip in the model. Missing or ambiguous mapped clips reject a replacement. Omitted mappings are allowed and reported as degradation. A zero-second transition switches immediately.

Normal speaking and mouth movement follow actual endpoint playback. Preparing text alone does not claim audible speech. All schema versions keep the same resource limits, private catalog access, hash checks and safe between-turn selection semantics.

Schema `1.2.0` adds optional `face` data with at least one `gaze` or `blink` mapping and requires `capabilities.facialAnimation: true`. Older versions reject this field. Gaze declares one to four unique node names, unit and perpendicular local yaw/pitch axes, and positive radian limits of at most 0.35 yaw and 0.25 pitch. Blink names one clip with a closed pose at its endpoint, a period of 1–30 seconds and a duration of 0.08–1 second shorter than the period. The closed pose is limited to 192 position/quaternion/scale tracks across 64 nodes. Missing or ambiguous targets, unsupported tracks, nonfinite poses and ownership overlap between mouth, gaze and blink reject the replacement. Asset-specific names and axes belong only to the separately supplied pack.

The shared `presentation-motion.js` module restores its prior overlay before each body/speech update, then layers eyelids and gaze over that frame's pose without accumulating rotations. Idle uses a small bounded gaze drift and deterministic blinks; participant attention centers gaze. Ambient face motion is disabled by the browser's reduced-motion preference. Explicit previews remain available. This is presentation animation and does not imply gaze sensing, person recognition or audience evidence.

The authenticated presentation operation `clearSessionOverride` requires the current override revision and the same CSRF, audience and between-turn checks as selection. Clearing retains an internal revision marker, so stale writes cannot recreate an older override. That marker is not an appearance package and is omitted from the effective selection; `overrideRevision` allows the next explicit session choice. Restores discard session selections and their markers while preserving endpoint defaults.

Runtime self-context reflects the saved session override or endpoint default as `configuredNotObserved` only when its pinned package is in the validated catalog (or it explicitly selects the built-in neutral presentation). A missing or changed package is `unavailable`; no saved choice is `notConfigured`. Shared/unknown protected audience state withholds the presentation configuration. Only an opaque selection revision reaches cognition: package names, paths and mappings remain outside the prepared request. This metadata does not observe renderer activity, physical visibility, camera input or playback. The same host-owned projection reaches typed and transcribed-audio requests; a client cannot supply its own presentation truth.

Schema `1.3.0` adds optional `speech` data for cached acknowledgment cues: a `cueSet`, a `poses` object mapping cue symbols to named pose clips, and optional `transitionSeconds` from 0 to 0.1 (default 0.04). It requires an existing amplitude mouth mapping and retains `capabilities.lipSync: "amplitude"` for ordinary answer playback. Older schemas reject `speech`. Each cue uses the terminal pose of exactly one declared clip; it does not replay that clip on a wall-clock timer. Packages may declare up to 32 cue symbols, 192 transform tracks per pose, 64 target nodes and 2,048 ordered finite keyframes per track. Only position, quaternion and scale tracks are supported. Ambiguous targets, invalid values and overlap with blink/gaze ownership reject the replacement.

The shared `presentation-speech.js` overlay follows the same `AudioContext.currentTime` sample offset and playback-segment identity as the cached audio. It restores its previous overlay before evaluating the next body and ordinary-speech pose. Stop, silence, an incompatible cue, a new segment or a rewound sample clock drops prior transitions. When answer audio preempts a cue, its amplitude pose takes control in the same frame. Reduced motion does not suppress speech-driven mouth movement. A compatible mapping is required for synchronized cues; without one the cue is skipped unless the user explicitly allows audio-only fallback. No catalog download, alignment or asset preparation is performed on turn acceptance. Avatar-specific pose names and calibration stay in the separately supplied package; fixture verification does not establish perceptual synchronization.
