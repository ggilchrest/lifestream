# Appearance packages and animation previews

An appearance changes presentation independently of Assistant identity, memory and voice. Packages remain separately supplied through the authenticated, digest-checked resource catalog. They contain bounded data and declared assets, never scripts or remote resource URLs.

In **Conversation**, select an **Appearance** and **Apply to** scope, then click **Apply appearance** between turns. A failed replacement retains the current display. **Restart display** recovers a failed renderer without replaying speech.

Expand **Preview animations** to inspect the applied appearance. Select an **Animation state** and click **Preview animation**. The preview lasts five seconds; **End preview** returns to the conversation immediately. Starting a real turn, changing the audience, leaving the page or replacing the appearance ends the preview. Preview does not save a selection, alter the Assistant, write memory or synthesize speech. **Speaking motion only** is a visual animation preview, not an audible-speaking claim or a lip-sync test.

The status distinguishes a declared animation, an idle fallback and an absent mapping. Select a **Face motion** and click **Preview face motion** for a five-second blink, left, right, up, down or centered-gaze preview. **End preview** ends either kind of preview. An appearance without the selected mapping explains that limitation. These controls do not supply phoneme alignment. Human inspection remains required for convincing motion, transitions and appearance quality.

Package schema `1.0.0` retains its existing `idle`, `listening`, `speaking` and `mouthAmplitude` animation mappings. Schema `1.1.0` additionally supports `preparing`, `interrupted`, `working`, `waiting` and `failure`, with optional `transitionSeconds` from 0 to 1; the default is 0.15 seconds. Each mapping must name exactly one clip in the model. Missing or ambiguous mapped clips reject a replacement. Omitted mappings are allowed and reported as degradation. A zero-second transition switches immediately.

Normal speaking and mouth movement follow actual endpoint playback. Preparing text alone does not claim audible speech. All schema versions keep the same resource limits, private catalog access, hash checks and safe between-turn selection semantics.

Schema `1.2.0` adds optional `face` data with at least one `gaze` or `blink` mapping and requires `capabilities.facialAnimation: true`. Older versions reject this field. Gaze declares one to four unique node names, unit and perpendicular local yaw/pitch axes, and positive radian limits of at most 0.35 yaw and 0.25 pitch. Blink names one clip with a closed pose at its endpoint, a period of 1–30 seconds and a duration of 0.08–1 second shorter than the period. The closed pose is limited to 192 position/quaternion/scale tracks across 64 nodes. Missing or ambiguous targets, unsupported tracks, nonfinite poses and ownership overlap between mouth, gaze and blink reject the replacement. Asset-specific names and axes belong only to the separately supplied pack.

The shared `presentation-motion.js` module restores its prior overlay before each body/speech update, then layers eyelids and gaze over that frame's pose without accumulating rotations. Idle uses a small bounded gaze drift and deterministic blinks; participant attention centers gaze. Ambient face motion is disabled by the browser's reduced-motion preference. Explicit previews remain available. This is presentation animation and does not imply gaze sensing, person recognition or audience evidence.
