# Local v0.1 candidate

This is an implementation candidate, with separate technical, real-provider and Human acceptance. The existing S083/S084 Human acceptance is unchanged. It does not accept these new features.

## Run

Build with `pnpm build`. Configure the existing selected development providers and supply their credentials only to the server environment. Run:

```sh
pnpm candidate --directory /operator-local/candidate --profile ai5090 --presentations /operator-local/presentation-packages
pnpm desktop --url http://127.0.0.1:43182/control/#conversation
```

Use real operator-local paths outside connected repositories. The launcher creates an installation token file with restrictive permissions. Enroll the Owner through local sign-in. Credentials and private files are not browser configuration. The server binds loopback only and refuses to substitute fixture providers. `--profile test` explicitly selects synthetic providers for development tests.

A required provider outage leaves authenticated administration available, including when the candidate starts during the outage. The startup report says `administrationOnly`; `/health` and `/health/ready` return 503 with the failed providers and `acceptingInteractions: false`, while `/health/live` remains available. Conversation admission stays closed. Readiness checks observe recovery of the same selected providers without substituting fixtures or requiring a candidate restart. Configuration, database or listener failures still stop startup.

The browser and sandboxed Electron host use the same conversation surface. Electron permits only this local origin, denies popups and embedded webviews, and permits audio input only. It never enables a camera. Native device/perceptual acceptance remains pending.

## Presentation packages

The generic application starts with a procedural neutral reference and does not require a private asset library. A separately configured directory contains `index.json`, a list of at most sixteen package IDs, and one directory per ID containing `manifest.json` and its curated resources. Private packages are visible only to the installation Owner by default; an explicit principal binding is supported.

The manifest declares schema/version/identity, `three-glb.v1`, one GLB or glTF model, exact resource sizes and SHA-256 digests, framing, semantic clip names, supported features and a neutral fallback. Schema 1.0.0 includes idle, listening, speaking and an optional `mouthAmplitude` clip; 1.1.0 adds preparing, interrupted, working, waiting, failure and bounded transitions. Every declared clip must exist exactly once. Optional morph-target mouth mappings are also supported. Package data cannot contain scripts, arbitrary URLs or undeclared model dependencies. Traversal, symlink escapes, incompatible required extensions, changed bytes and resource-bound violations fail closed. Individual resources are bounded to 192 MiB and a package to 384 MiB. See [appearance previews](presentation-packages.md) for temporary state inspection and explicit fallback.

Apply appearance between turns. The client prepares and validates the new model before committing the selection. Loading failure retains the current appearance. Replaced GPU resources and image bitmaps are disposed. The chooser supports an endpoint default and a session override without changing the Assistant profile, voice, persona or memory. A principal-scoped client binding persists the logical endpoint across sign-ins; browser and native profiles have separate bindings. Session overrides do not carry into a new authenticated session. Apply disclosure again after sign-in.

Speaking and mouth motion sample the actual scheduled PCM at `AudioContext.currentTime`; generation alone is not audible speech. Stop retires the interaction and clears the sample queue. Amplitude animation is explicitly labeled and makes no phoneme or viseme claim. The existing BehaviorController owns monotonic semantic state, trace identity and transient expiry. Restart display recreates a failed WebGL surface. Native shell inspection is distinct from physical/perceptual, clock-skew, prolonged-session and full semantic-mapping acceptance.

## Automatic memory

Select an owned relationship, review its scope and choose **Apply memory mode**. Once enabled, ordinary useful owner statements can enter durable memory without per-item review. The worker uses the selected inference provider asynchronously, admits only validated exact attributed quotations, and writes through the existing memory/lifecycle repository. It distinguishes pending work from successful persistence. Project context, decisions, conventions, preferences and experiences are supported; general questions and transient chat need not create records.

Unknown speakers cannot create owner memory. Secrets and unrelated third-party statements are excluded. The initial implemented attribution path is authenticated typed owner input; physical voice identity is not inferred. One worker, six proposals per job, two automatic attempts, 60-second extraction deadlines, 128 pending jobs, bounded context and short-lived raw queue payloads limit work. Prepared extraction survives a restart without repeating the provider call after a persistence failure. Completed jobs discard raw input and extraction payloads.

An unresolved difference withholds conflicting records from context and marks review needed. An explicit owner correction supersedes the prior same-topic records through lifecycle events. Forget memory removes payloads, records a durable exclusion and applies the existing recovery journal to dependent context. Admission rechecks collection policy and known forgotten content; topic matching quality remains part of real-provider acceptance. Existing inspection, correction, suppression, forgetting and recovery paths remain the owning controls. Automatic admission neither trains a model nor changes persona, tools, grants, source access or external world truth.

## Audience privacy and the native endpoint

The candidate launcher enables audience enforcement. It starts unknown. Select a session endpoint, then use **Only me · 5 minutes** if appropriate. This is an expiring manual fallback, not automatic presence proof. **Shared audience** restricts private context and displays; **Clear declaration** removes the manual assertion. The **Refresh audience** control reads current evidence. A lost or stale evidence channel protects the display.

The trusted source adapter accepts only enrolled source identifiers, matching owner/endpoint scope, fresh evidence and explicit coverage. A known second participant overrides a solo declaration. Unknown coverage does not assert solo. Source expiry or a restrictive change fences prepared context and speech, clears old dialogue and protects private views. Ordinary generic conversation remains usable. Automatic memory admission is limited to the approved owner scope while private context is permitted.

Electron uses the same web core, a persistent endpoint partition, sandbox and context isolation. Its only preload interface receives lock restrictions; it exposes no provider credentials or filesystem API. OS lock/suspend protects the endpoint. Unlock requires fresh evidence or a new scoped declaration. Camera requests and external navigation are denied. Native window inspection and a simulated OS lock passed; physical capture, audibility, OS lock and automatic sensor coverage still need the applicable Human/environment evidence.

## Incident evidence

Optionally pass `--incident-review /operator-local/consumer.json` with a loopback PWCE origin, `worldRef`, `siteRef`, server-only `token`, and explicit `replay` label. That file must be outside Git. The consumer pins `pwce-incident-evidence.bundle.v1` and validates producer-owned schemas; capture and retention remain PWCE responsibilities. It grants no new recording authority and does not change the World/action provider selection.

Conversation includes **Refresh incidents**, **Review retained media**, **Close retained media** and **Hide incident evidence**. Only the installation Owner in a permitted personal session can use these routes. Media is bounded, digest-checked and reauthorized after transfer. It never enters prompts, memory or traces. Audience/session/Assistant changes and hidden pages clear media, with another current access check every five seconds while displayed. Pending, failed, expired and incomplete coverage remain explicit. A replay is clearly labeled; Studio owns retry and source administration.
