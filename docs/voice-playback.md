# Conversation speech playback

Browser and native conversations share the same playback controller. Speech starts with an 80 ms scheduling cushion after the first admitted PCM frame. Subsequent frames keep their contiguous playback positions while there is queued audio. A late frame can resume with a 20 ms cushion instead of restarting the full startup delay.

These values describe software scheduling, not end-to-end response latency or physical audibility. Recognition, turn detection, model generation, synthesis, transport and the output device still contribute delay. A provider gap can still produce silence. Playback-driven mouth animation follows the actual scheduled samples and stays silent during a gap.

Stop, interruption, privacy changes and connection loss discard queued output and fence retired responses. Reducing the scheduling cushion does not change these controls, microphone endpointing, provider selection or speech projection.

For acceptance, compare first admitted PCM to the first scheduled sample and measure actual end-of-turn to audible speech separately. Exercise normal replies, delayed chunks, gaps between speech segments, Stop, shared/unknown audience, reconnect and a subsequent reply. Record any starvation, click or perceptual discontinuity. Keep the existing 900 ms median and 1,500 ms p95 first-spoken-word objectives until actual acceptance evidence satisfies them.

Ordinary voice keeps its server audio lease while response PCM remains queued at the endpoint. The browser and Mac controller send a trace-bound `playbackSettled` report after the last buffer ends, or after Stop has disconnected all queued sources. Completion requires successful synthesis and exact received-sample accounting. A cancellation request alone does not release ownership; stale, foreign and early reports do not release it either. A disconnected or older client that cannot report settlement conservatively keeps the lease until its existing 180-second turn expiry. Provider cleanup must settle before another turn uses that transport.

The development voice page follows the same reporting rule. Headless qualification scripts explicitly discard PCM and report `stopped`; they do not claim playback. These reports measure endpoint software state, not physical silence, audibility or Human reception. Output-only Initiative speech also retains ownership through the same endpoint settlement, alongside its existing delivery-ledger receipt checks. A socket report does not replace that ledger, and cancelling an opening alone does not prove local sources stopped. HTTP voice previews now retain custody after HTTP EOF. Both saved-voice and development previews report actual completion or local stop through the authenticated preview settlement route; the original expiry also stops browser output. A privacy change can still report its own stopped output while private content remains withheld. Headless collectors report discarded PCM as stopped. Physical device arbitration and a complete cross-endpoint handoff remain separate requirements.
