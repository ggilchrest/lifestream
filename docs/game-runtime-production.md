# Authenticated production game runtime join

`ServerOptions.gameRuntime` is a separate trusted composition contract beside
`gameHost`. It requires a production profile, existing local-password auth,
loopback, independent native source qualification and a finite user-consent
resolver. The original `gameMemory` injection remains test-only. No profile,
account, transport, pairing key, native process, start occurrence or model call
is created by these options.

`resolveApproval(scope)` returns the exact approved ActivityScope, approvedUntil,
maximumRunMs (1–120000), maximumPlanningSteps (1–64), observations=true,
campaignJournal=true, and separate controllerInput/memoryEpisodes decisions.
The operator resolves actual Human consent and independently qualified source;
attachment assertions are insufficient. Every check re-resolves the same finite
approval. Scope/approval/source/auth/audience/endpoint/relationship changes fence
the run. An optional memory source also needs matching independent retention
consent, existing automatic-memory policy, meaningful recorded-source grounding,
source/correction/privacy currency and the existing forgetting checks.

An authenticated `GameHostJoin` optionally receives `runtime` with scoped
`preparePlanning(selection,bounds)`, `runPlanning(step,publication)`,
`publishEpisode(episode)`, `isCurrent`, `controllerCurrent` and `close` methods.
Preparation uses the existing server's real conversation, persona, relationship,
canonical nine-section activity view and minted binding. Planning uses the
existing provider and DiscoveryAdministration coordinator and durable repository.
No second coordinator or provider, fabricated Human message or foreground
priority is created. A copied/repeated step cannot be replayed. Closing/expiry
cancels only the exact active planning key; native neutralization/pause still
requires Windows' independent old-lease shutdown evidence.

Shared P2 retains the original10ms caller/250ms native-slot limits. The default
llama-cpp-local profile remains unqualified. An optional trusted operator
`inferenceQualificationFor(selection)` port can supply independently reviewed
exact deployment/model/configuration/envelope evidence. Its selection digest,
qualification reference, bounds and current predicate must stay pinned; missing,
changed or unqualified evidence fails closed. HTTP/model/client metadata and
passing a few timing samples cannot manufacture this evidence. Generic provider
priority advertisement is unchanged; no shipped profile enables the port.

Production episode publication additionally requires the corresponding current
authenticated run. Historical recall uses the retained-source and privacy policy,
not a renewed play lease. Publishing memory can invalidate the prepared context;
the old attachment must be fenced rather than silently renewed. Publish bounded
episodes at the chosen journal/memory boundary. Model summary and valid schemas
alone are not recorded native evidence or meaningful grounding.

Windows remains responsible for qualified observations/decoder, receipts,
monotonic usage/reconciliation, fresh dispatch/capability admission and exact
old-lease shutdown. Existing durable claim/entry CAS and controlSave suppression
remain unchanged. This source patch activates no live gameplay or memory.

Supply independently qualified `native` ports, the existing campaign owner

`maximumSteps` is 1-64, `maximumRunMs` is 1-120000, and `maximumCommandMs` is
1-5000. Native `sourceCurrent(scope)` checks the reviewed source independently;
`sourceAvailable(scope,pinsDigest)` also checks the exact requested pins.
Campaign `selectPlanning` returns a genuine selected campaign context and bounds.
The helper prepares and runs it through `join.runtime`, then obtains an actual
fresh controller selection from `prepareController`. It supplies no model,
provider, coordinator, context identity, default qualification, or synthetic
decision. `recordSettledStep` must commit the qualified campaign journal and may
return its source-grounded episode for the existing production memory intake.

One composition admits one attachment and one repository. Stop, expiry,
source-function changes, suppressed planning, and context retirement fence
further work. `stop()` initiates and awaits the independently qualified exact
old-lease shutdown, including while a campaign callback remains unresolved.
An unconfirmed shutdown reports `requiresReconciliation`. Memory publication
that retires the prepared context ends this attachment rather than renewing it.
The native shutdown implementation must itself have qualified finite transport
and readback limits. This orchestration source is not evidence of live gameplay,
