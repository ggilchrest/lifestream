# Meaning-based conversational memory

Ordinary authenticated turns enter the existing consent-controlled idle worker. The worker asks the configured inference provider for useful, qualified proposals; first-person wording and question patterns do not define what is memorable. It can return zero candidates. Rapid unattempted turns coalesce within their owner scope; this optional mechanism can omit earlier conversational material.

The separate worker task accepts strict version-2 JSON with up to three candidates and 4096 UTF-8 bytes per turn. It pins turn, known session/message references, source digest and consent revision. Each candidate includes an exact quote, proposed interpretation, relationship scope, participant attribution and uncertainty. Advice, hypotheses, questions, quoted speech, jokes and reported views remain distinct. Structural acceptance does not verify meaning or truth. The first mechanism accepts source-only proposals with empty dependency references; proposals deriving claims from other records are rejected.

Prepared proposals bind canonical bytes to their retry identity. Persistence retries reuse the preparation; changed bytes conflict. Repetition does not reinforce truth. Existing automatic admission, topic-conflict review, explicit corrections and forgetting remain responsible for lifecycle changes. New records retain unverified factuality and use a zero legacy confidence value, not a semantic truth score. Prepared context carries the quote, proposed attribution and uncertainty within the existing allocation.

Source removal cancels queued/running/prepared work, erases source-bound payloads and preserves a non-payload tombstone. Policy withdrawal fences reads immediately; reapproval cannot revive proposals from an older policy revision. Reviewed corrections preserve source custody and replace current content without copying the superseded meaning, attribution, uncertainty or speech-act interpretation. Original records and correction events retain the history. Older corrected rows receive the same projection fence when read. Existing authenticated game-advice dependency retirement handles game descendants; independent relationship advice is not owned by a game episode. The host-only source-revocation method creates no new administration endpoint or external effect.

The worker retains one-at-a-time execution, foreground preemption, existing attempt limits and a 60-second optional-work ceiling within the 24-hour queued-source lifetime. Completed custody receipts persist while retained records require them, within the existing 10000-row capacity. Rejected sensitive metadata is never prepared. No metadata channel is added to foreground inference and no prose delimiters or tool calls are used to carry proposals.

Synthetic fixtures verify custody, persistence, qualification and cancellation. Actual selected-model semantic quality, independent held-out recall, paired first-text/audio and resource measurements remain separate qualification work. The inherited 900 ms median / 1500 ms p95 onset objectives and earlier failures remain unchanged. This source does not claim observed gameplay or successful cross-game application. Windows directory-fsync failures remain unresolved; durability checks are retained.

Authenticated retained-owner inspection, reviewed correction and forgetting use a separate exact-owner administration path. A current private session, personal endpoint, audience and owned relationship remain required. Withdrawal keeps current conversational context, semantic retrieval and learning disabled. Administration neither enables policy nor gives another participant access; erased payloads stay erased. Superseded source history remains inspectable while current interpretation is separately fenced.

Explicit authenticated memory search uses the existing inference provider to judge the meaning and relevance of a current query. It is an optional task sharing the existing idle-worker lease, foreground preemption and 60-second ceiling; no call is added to ordinary utterances. The configured provider receives only current eligible owned records, their qualified content and proposed meaning, and can select zero. Structural checks validate exact query/source digests, ids, revisions, unique references and bounds; they do not certify relevance or truth. Returned records preserve source attribution and factuality without reinforcement.

The task considers at most 240 current records in at most eight batches of 32 records/24 KiB each, then uses one bounded ranking call across selected references if needed. Query size is at most 2000 UTF-8 bytes, provider payload at most 32 KiB, output at most 4096 bytes/2048 tokens per call and results at most 20. Every eligible candidate is considered or the whole request fails closed; exceeding a batch/reducer/deadline bound does not silently clip a later source. Scope, consent, current source/lifecycle inventory and provider revision are rechecked before use. Busy, revoked, disconnected, malformed, oversized, incomplete or cancelled selection returns unavailable rather than unrelated records or a fabricated empty success. There is no new provider, dependency, memory engine, persistence table, truth score or effect. The explicit owner-search task does not cache its result.

The synchronous repository search is explicitly literal-only. The older query-independent helper is named searchCandidates and proves bounded candidate acquisition only; production semantic search does not use it. The optional ordinary conversation experiment below preserves existing callback, audience and lifecycle controls. Selected-model relevance quality and first-text/audio/resource measurements still require separate qualification. The semantic request path is the existing private-owner POST /api/admin/v1/assistants/<id>/memories/search; fixture-only direct administration retains literal search and is not semantic acceptance. Source fixtures use scripted relevance judgments and a synthetic canonical-adapter HTTP witness, not a live provider.


The ordinary text route has an optional trusted-host composition seam, disabled when `ServerOptions.conversationMemoryRecall` is absent. Client JSON cannot activate it or supply selected references. Audio, activity-origin turns and shared/unknown audiences do not attach the seam. Configuration is captured immutably and requires exactly `mode`, `waitBudgetMs`, `fallback: 'ordinary-context'`, and `warmOnMiss`. No existing profile activates it. This is preparation for a product timing decision, not a new default or a requirement to ask explicitly for memory.

`mode: 'idle', waitBudgetMs: 0` consumes only a completed exact-query projection. An unseen query uses ordinary context immediately. With `warmOnMiss: true`, a successfully completed ordinary turn may queue that query for the existing worker; visual intake and source admission keep priority. A later identical query can consume the completed result without adding a selector call. This does not cover a first unseen paraphrase, nor does a projection for a different query establish coverage. The queue coalesces the latest query per owner scope and holds at most 32 queries of at most 2000 UTF-8 bytes each for 55 seconds. At most 32 projections hold references and scoped currency predicates in volatile process memory, also within the selector's 55-second freshness bound. Host currency callbacks can retain their scoped preparation snapshot. No query/result persistence, source reinforcement or evidence record is added.

`mode: 'bounded', waitBudgetMs: 1..5000` may attempt the existing idle selector before foreground admission, with an abort signal for the configured provider-wait budget. Busy, interrupted, malformed, stale or budget-exhausted work uses the ordinary context fallback; successful zero selection remains distinct. Fresh results are request-bound and do not enter the warm cache. The wait budget is not a ceiling on total preparation elapsed time: bounded synchronous custody reads, compilation and scheduler overhead add time. Per-response inspection exposes measured `preparationMs`, budget, coverage (`fresh`, `idleWarm` or `miss`), state, reason and selected reference count. A successful selection reports provider calls; unavailable fresh selection leaves that count unknown. Synthetic loopback benchmarks distinguish this preparation cost from complete HTTP response time. Neither is first-text/audio onset or actual-provider performance.

Current semantic references are host metadata containing exact ids and revisions, never new record text. The compiler checks them against eligible memory records, preserves model order within the existing optional allocation, withholds unselected optional memory records, and keeps mandatory corrections. It retains the existing four-record, 512-byte optional and 8192-byte total bounds. Consent, scope, provider revision, complete source/lifecycle digest and freshness are rechecked through preparation, canonical prompt assembly and every streamed output chunk. Source attribution, reported/advice status and uncertainty remain in the original qualified projection. Retrieval does not verify truth or authorize an action.

The existing numeric relevance threshold represents lexical allocation, not a calibrated semantic score. The optional seam currently supports only its existing default value (0.7); nondefault thresholds retain ordinary allocation. Zero callback frequency or personalization intensity prevents the seam. There is no invented score or silent mapping of another threshold. Synthetic stream fixtures demonstrate an attributed paraphrase reply, literal distractor exclusion, first-query fallback/warm coverage, successful zero, late cancellation and consent/source/provider/authorization fences. The authenticated application-route witnesses remain separate durability and integration qualification. Default activation, first-new-query coverage, selected-model held-out relevance, paired onset/resource performance and audio behavior remain open decisions or qualification work.
