# iOS Assistant v0.1

An operator-local Capacitor 8 application reuses the existing Three.js presentation runtime and packages generic interface code. Swift owns microphone capture, Apple voice processing, speech WebSocket transport, playback and background lifecycle. The app connects to an authenticated Lifestream runtime for conversations, memory and AI services. Renderer code, selected models, textures and animation resources are bundled on the phone; no presentation assets are fetched from that server. The generic build contains only the neutral reference. A separate operator-local build can bundle private presentation packages without placing them in Git. No inference model, persona, provider credential or backend is bundled.

## Build and run

Requires Node 24+, Google Chrome for the UI test, Xcode with iOS SDK, and an existing configured Lifestream account and Assistant. The independent npm lock keeps iOS tooling out of server installation. First run the normal repository dependency installation and `pnpm build` so integration tests can use the existing server packages.

```sh
cd apps/ios
npm ci
npm run sync
npm test
npm run test:native
open ios/App/App.xcodeproj
```

Choose the App scheme, your own signing team and a connected iPhone. No team, provisioning profile or signing secret is committed. The bundle identifier is `org.lifestream.assistant`; adjust locally if your team's provisioning requires it. `npm run sync` reattaches the local Swift package after Capacitor regenerates its dependency list. Bundled web output and build products are ignored.

An unsigned compile can be reproduced with:

```sh
xcodebuild -project ios/App/App.xcodeproj -scheme App -sdk iphoneos \
  -configuration Release -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

Release accepts HTTPS server origins only; Debug additionally accepts loopback HTTP for isolated local tests. It never accepts embedded credentials, a path/query in the origin, certificate bypasses or redirects. The native bridge is restricted to bundled `capacitor://localhost` content and a small API allowlist. Password/code form fields are cleared after sign-in. Following the operator's explicit save-credentials request, native transport stores the successfully verified account password, server origin, account name and session cookie in device-only Keychain storage without iCloud synchronization. Passwords, cookies and CSRF never return to JavaScript. Reopening validates the saved session; when it has expired, native transport attempts one password sign-in. It refreshes CSRF and requests a fresh five-minute Only-me declaration after authenticating, with no microphone. Authenticator codes are never saved: a sign-in that supplied a code requires a fresh manual sign-in after session expiry. Leave that field blank when the account has no authenticator. The current backend does not return enrollment metadata, so this conservative rule uses prior code submission. A failed saved-password sign-in removes that password to avoid repeated lockout attempts. Network failures retain credentials for retry. Sign out clears password/session custody even if remote revocation fails, and reports the latter. Changing origin/account clears prior credentials. Server authentication lifetime is unchanged. An account with permission to administer the selected Assistant is required in this first app; subscriber-only mobile accounts are not implemented.

**Physical connection prerequisite:** the current local-password server deliberately accepts only loopback traffic and checks Host/Origin. A physical iPhone cannot reach `127.0.0.1` on the Mac. This change opens no listeners, installs no tunnel, weakens no server guard and deploys nothing. A separately approved private TLS connection that preserves the authenticated backend boundary is required before real phone testing. Do not enter credentials into an untrusted proxy. The server source must include this change's additive `personalCompanion` binding support; the previously installed beta is not silently replaced.

## Build with local appearance packages

Use the following from `apps/ios`, substituting an existing validated package catalog, selected package ID and a **new output directory outside all Git checkouts**:

```sh
node scripts/package-private.mjs /absolute/private/mobile-build /absolute/private/packages selected-package-id
open /absolute/private/mobile-build/ios/App/App.xcodeproj
```

This creates the complete Xcode project, preserves current local signing settings, bundles the shared renderer and copies only declared, digest-checked resources. Package validation rejects missing, changed and undeclared external dependencies. The first selected package is the local default. Neutral reference remains available. No model conversion or animation substitution occurs. Each resource is limited to 64 MiB. Do not run Capacitor sync in the generated project: regenerate a new project using this command to update source or assets. Ordinary `npm run sync` in the source tree produces the neutral generic build.

Assistant choice, per-Assistant appearance choice and per-package animation availability are saved in the same device-only record. They survive restart and sign-out for the same server/account; switching server or account starts with separate defaults. Private labels and appearances still require current audience permission. Background-listening opt-in is deliberately reset on cold launch. Desktop/server appearance selections are not changed. The UI still requires a valid private-audience decision before displaying private packages and clears them when locked, shared or expired. Bundling makes bytes available to someone who can extract the app; these display controls are not encryption or asset revocation. Keep the private project and app operator-local.

The intended deployment has Lifestream and AI services on the private server and renderer/native audio on the phone. A reachable, authenticated HTTPS/WSS endpoint is still required for conversation. Moving the runtime to another host requires a compatible build, explicit data/identity continuity and a private ingress configuration; changing the hostname alone does not remove the loopback/Host/Origin checks. No public listener or data migration is enabled by packaging.

## Main and Settings panes

The main pane contains the Assistant view, transcript, text composer and Send, Start/Stop, microphone selection, audio diagnostics, three activity lights, microphone meter and an audience status indicator. Only me activates automatically on authenticated open; the former Only me and Shared / unknown buttons are removed. Settings contains connection/account, Assistant selection, bundled appearance, animation toggles and background-listening opt-in. Back to Assistant returns without changing the conversation. Status messages remain visible in either pane.

The animation list is derived from declared body clips in the bundled appearance. Each distinct clip can be disabled or re-enabled for automatic use; shared semantic mappings use one switch. Disabled clips stop immediately, including during a transition, and choices persist for that package digest. Undeclared/missing animations are not invented or downloaded. System Reduce Motion remains authoritative. Speech output and audio processing do not depend on these body-animation switches.

## Included behavior

- Saved native account credentials and automatic session restoration; fresh TOTP when required. Existing Assistants and session appearance selection.
- Audio input, LLM/backend and output lights show observed native stages, with visible labels and error states. Input level reflects captured PCM; active input is distinct from a successfully detected/sent utterance. Raw tap buffers and converted buffers are counted separately, with the actual input format shown. Engine readiness begins an eight-second initial capture window; established capture stalls after three seconds without converted samples. No-raw-buffer, conversion and stalled-capture failures stop with distinct explanations and retain their volatile counts for inspection. Start clears the prior attempt; old callbacks cannot stop or affect its replacement. The provisional speech gate processes fixed 20 ms windows independently of the hardware callback size.
- Typed Send uses the existing authenticated messages API without starting capture or speech playback. Backend processing remains visible until the validated text response arrives. Stop cancels the request; changed audience, session or display discards late replies. Enter sends; Shift+Enter inserts a newline. Private transcript requires current Only-me permission. A fresh explicit Send requests the default five-minute declaration before dispatch; a new draft can be entered after expiry, while prior private transcript and drafts remain cleared.
- Shared renderer/core with digest-checked bundled appearance resources. All model, texture and animation loads are local; the native API bridge rejects remote presentation requests. Private packs render only for a permitted foreground display.
- This initial mobile build limits each appearance resource to 64 MiB; larger existing desktop packages produce an explicit error and retain the current display. Smaller mobile assets must be authored separately; the app does not rewrite private packs.
- Native AVAudioSession play-and-record/voice-chat, AVAudioEngine voice processing, conversion to 16 kHz mono PCM input, native 48 kHz PCM output. No browser microphone or WebAudio lifetime dependency.
- Native bounded energy gate: 160 ms qualification, 300 ms pre-roll, 600 ms silence commit and roughly 20 second utterance cap. This is provisional energy gating after Apple processing, not Silero/speaker recognition and not noise/echo acceptance.
- Sequenced speech messages, retired-turn fences, bounded receive/playback backpressure, cancellation and playback settlement after native played-back callbacks. Foreground amplitude animation is coarse callback-driven; no phoneme timing or precise lip-sync is claimed.
- User-selected continuation when locked. Native network/audio and audience checks continue independently of suspended JavaScript. Lock screen shows only a generic title and Stop/Pause/headset-toggle commands. Resuming after an OS kill or call requires a tap; no wake word or boot-time recording.
- iOS system Bluetooth HFP routing; newly available routes rebuild the native session when needed and recheck audience without combining partial PCM from two routes. Removing headphones stops audio rather than continuing a private reply on the speaker. The native Microphone sheet always offers System default and iPhone microphone, plus up to eight currently exposed external microphones. Discovery can be empty while the session is inactive; the sheet explains this. Choosing an input stops the current conversation and applies the preference on the next explicit Start. Start waits up to four seconds for iOS to route that input before installing the capture tap; Stop cancels the wait. Specific unavailable inputs fail visibly without switching to another microphone. Selection is local to the current app process. Bluetooth input selection can also move output to the paired headset; use iOS Control Center for playback destinations.
- Audience refresh at most every 500 ms during active audio, with a 1.2 second request timeout and local expiry check. Unreachable/revoked/changed scope stops audio. The operator-selected Only-me default requests a fresh manual declaration on authenticated open/reopen, explicit Start and idle Send. Each declaration expires after five minutes; the app never renews one during an active conversation or when merely polling privacy. Active foreground resume only reads audience state. Expiry and remote changes still stop audio and clear private content; a new Start or Send requests the default again, subject to current server permission. These declarations do not detect nearby people or establish speaker identity. No native capture starts on opening the app.
- Private display clears when hidden or audience changes; a native shield covers app-switcher snapshots before backgrounding. Shared/unknown mode uses generic labels and withholds private transcript and appearance. No camera is used.

Automatic memory remains a server policy and is not newly enabled by this app. Existing privacy and voice-owner admission rules apply. Mobile push, offline inference, automatic speaker identity, phone-call answering, automatic conversation migration from the Mac and Android are outside this first build.

## Acceptance journeys — physical iPhone required

Record iPhone/iOS version, source revisions, selected runtime/provider identities, network route, headset model and result for each journey. Software/fixture results do not sign off the native audio route. Use a neutral Assistant and non-sensitive prompts first.

1. **Install and connection:** launch; open Settings and return to the main pane; try invalid address, bad password and bad TOTP; confirm useful failure and cleared secret fields. Connect successfully; select an existing Assistant. No microphone starts before Start listening. Terminate/relaunch after signing in: verify server/account and Assistant choice restore, the valid session reconnects, Only me is active with a new five-minute server lease and no microphone starts. Repeat with server offline, then Reconnect saved session; repeat after remote session revocation or administrative expiry and expect one automatic password sign-in. Verify fresh-code prompting for a TOTP account, offline retry and a changed password without repeated login attempts. Sign out and confirm controls/display clear; relaunch must not sign in automatically. Changing server/account must never send the previous cookie to it.
2. **Automatic personal audience:** sign in and confirm Only me is active without audience buttons or microphone activity. Start listening directly, without a preparatory audience selection. In Settings, change Assistant and Appearance; Apply appearance and Refresh; verify the phone selection survives Refresh and restart without changing the desktop selection, package failure handling and continued usable conversation controls. Set shared/unknown or a restriction through the server while a request is active; private content must clear and the app must not replace that decision through polling. A rejected declaration must show an error without starting audio.
3. **Microphone permission and indicators:** deny the first prompt; Start must recover without a stuck spinner. Enable permission in Settings; tap Start again. Verify the OS microphone indicator and native route label. Input stays Starting until converted buffers actually arrive. Confirm the visible raw and converted buffer counters increase, then verify Listening and a moving level meter when sound reaches the device; detected speech, Transcribing, Generating reply, Preparing speech and Playing speech must reflect actual stages. If silent, record the displayed input/backend/output stage and error; do not infer a successful turn merely from Start returning. Tap Stop during setup, recognition, text generation and speech; no late audio or new turn may play.
4. **Speakerphone conversation:** speak several turns at normal and quiet volume; check recognition, output, echo, clipped beginnings, silence commits and noise rejection. Interrupt a reply with speech. Inspect actual provider evidence; an echo fixture response is not real-provider acceptance. Record latency separately against the existing objectives.
5. **Lock without opt-in:** leave Continue this conversation when locked unchecked; Start, then lock/app-switch. Microphone and output must stop. Reopen; tap Start to resume explicitly.
6. **Lock with opt-in:** check Continue this conversation when locked; Start while foreground; lock during listening and during a reply. Ask follow-up turns with the display locked. Native capture/playback must continue; the lock screen must contain no private title or transcript. Test Stop, Pause and AirPods stem/headset toggle; each must stop both microphone and playback. No remote Play action may restart listening.
7. **AirPods and routes:** start on speaker; connect AirPods, use Microphone and confirm both actual output and microphone route. Verify System default and iPhone microphone are always listed; choose an available headset input when exposed. Open/cancel the sheet without activating capture; select an input, then tap Start to apply. Try a selected headset that disconnects before Start: show an unavailable-input message rather than silently substituting the built-in mic. Test already-connected AirPods at Start, Bluetooth reconnect, wired headphones and supported routes. Repeat Start → Stop → Start at least five times on each route without force quitting; every attempt must capture, and Stop must remain stopped. Startup route notifications must not cause repeated Connecting/Starting cycles. A changed route permits one automatic recovery until converted audio arrives; failure leaves a visible error and manual Start. An old partial utterance must not become a new mixed-route request. Remove/disconnect headphones mid-private reply: audio stops without continuing on speaker; restart explicitly only after inspecting route.
8. **Phone/system interruption:** incoming call, Siri, alarm, audio-service reset and another recording app. Audio must relinquish appropriately, report the interruption and require a new Start; no surprise resumed recording or doubled output. Check other media resumes after Stop.
9. **Privacy while locked:** Automatic Only me + background opt-in; lock and wait past five minutes. The conversation must stop at expiry. Reopen while idle to establish a new declaration without restarting recording, or use Start/Send to begin a new bounded conversation. Returning to the foreground while audio remains active must not renew its lease or interrupt it. Separately revoke sign-in, switch audience or permission on the server during speech. No old reply may resume on reconnect. Reopening must not flash prior transcript/avatar in the app or app switcher.
10. **Network transitions:** switch Wi-Fi/cellular, lose the private tunnel, disable networking and restore it. Expect bounded fail-closed stop rather than a fabricated successful turn. Tap Start after connectivity returns. Verify no duplicate transcript, PCM replay, stale voice ownership or automatic private fallback.
11. **Long session and resource bounds:** run at least 30 minutes with repeated Start/Stop, foreground/background and route transitions. Use Start/Send between conversations to obtain a fresh five-minute declaration; there is no renewal during an active conversation. Inspect battery, thermal behavior, native memory, queue bounds, turn deadlines and quality. OS termination must leave no claim of continued listening; relaunch must not auto-record.
12. **Presentation and accessibility:** portrait/landscape and small screen, VoiceOver, Dynamic Type/reduced motion, appearance failure, wrong resource digest and GPU context loss. All account, Assistant, appearance, background, Start/Stop and Microphone controls remain usable; audience status must stay visible. Confirm the chosen bundled package loads with server presentation routes unavailable; no render dependency may contact a remote origin. Native speech must not depend on avatar loading or WebView animation. Check native microphone-sheet dismissal as well as opening it; changing selection stops any current conversation and requires Start. Expand/collapse Audio diagnostics and confirm it stays usable while states update. In Settings, toggle each available bundled animation off/on and verify actual body motion stops/resumes on the main pane. Restart and confirm those choices persist. Verify that an appearance with no declared clips shows an empty-state explanation and that Reduce Motion still applies.

13. **Typed conversation:** while alone, open the connected app, type a non-sensitive prompt and press Send or Enter. Verify the input and reply in the conversation, Backend processing during the request, Text received on completion, and no microphone or voice output. Shift+Enter must add a newline. Stop a pending request; no late reply should appear. Test an unavailable backend, expired audience and server-side shared/unknown while pending; show the appropriate error or privacy state and discard the private draft/result. After idle expiry, enter a new draft and Send: Only me must activate without starting audio. Empty Send remains disabled. Confirm labels and keyboard access at narrow widths.

### September 27 physical-input regression

The operator reported failed microphone capture on built-in and AirPods routes and a restart loop. Earlier software/SDK success is not physical audio acceptance. The bounded repair suppresses startup route storms, fences old privacy/timer/capture callbacks, uses per-graph conversion/queue custody and a supported 100 ms input tap request, observes engine configuration changes, and starts the capture watchdog only after engine readiness. Tests use synthetic PCM with the actual AVFoundation converter and deterministic lifecycle policy; they never activate a microphone. Re-run journeys 3, 4 and 7 first, recording raw/converted counters, meter, route, transcript and audible response, then the remaining lock/privacy/interruption journeys.


### September 27 AirPods route follow-up

A later AirPods test exhausted build5 recovery with zero buffers in the final graph. Those counters were reset during recovery, so they cannot establish what earlier graphs did. Full shutdown/recreation during recovery is replaced by retaining the active audio session and stopped voice-processing graph while refreshing taps, client-format connections and the speech transport. Explicit Stop still releases/deactivates everything. Voice processing uses matching capture/playback client formats, with the mixer converting server output PCM.

The Microphone sheet replaces the previous playback-only picker. Audio diagnostics shows up to24 volatile timestamped lifecycle events with port types, client formats, engine state and buffer counts across recovery, with no device names/identifiers, audio or transcript. A deliberate Start clears it. If the next physical attempt fails, expand this disclosure before another Start and capture its contents. Hardware capture remains unaccepted until actual input, transcript and audible reply pass.


### September 27 automatic personal audience correction

The operator observed that selecting an audience before Start made audio work, then explicitly selected Only me as the phone default and requested removal of both audience buttons. It retains the server's five-minute limit and does not turn expiry, remote restriction or lock-time privacy checks into silent renewal.
