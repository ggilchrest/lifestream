# Ephemeral development voice controls

The same-origin conversation test endpoints accept bounded `voiceSettings`: description (maximum 300 characters; no parentheses/control characters), seed (integer 0–2147483647), deliveryMode, pace/energy (0–1), and optional reference. These are session-test overrides, not a new canonical Assistant or VoiceProfile record. Defaults are empty description, seed 0, neutral delivery, pace 0.5 and energy 0.4. Apply snapshots them for the next live connection; each speech segment uses that snapshot.

`GET /v1/capabilities` advertises optional adapter extensions `voiceDesignControl: "voxcpm.voice-design.v1"` and `voiceReferenceControl: "voxcpm.voice-reference.v1"`. A synthesis request keeps canonical spoken `text` separate from `voiceDesign: {version, description, seed}` and `voiceReference: {version, dataBase64, sampleRateHz: 16000, transcript}`. Reference PCM is mono signed 16-bit little-endian, 2–20 seconds. Empty transcript means reference conditioning; a matching transcript requests continuation. Permission is enforced at the conversation boundary and is not a model parameter.

Before forwarding PCM, the adapter checks pre-audio `effectiveSynthesis.voiceDescription`, `seed`, SHA-256 `referenceDigest`, and `conditioningMode` (`reference` or `continuation`) against its request. Missing/mismatched acknowledgement fails closed. Old sidecars need not support these extensions; the browser disables unsupported inputs and the runtime rejects unsupported overrides. Delivery controls retain their existing canonical mapping/degradation behavior. Successful capability negotiation is cached per provider instance so a busy single-worker synthesizer cannot inconsistently disable supported controls.

Mapping `voxcpm2-map-2` advertises `spokenTextIsolation: "reference-anchor-v1"`. Vox's instruction convenience interface prepends ordinary text tokens, which can be spoken. The adapter therefore synthesizes a bounded, unplayed conditioning anchor first, then uses the isolated reference-audio slot to synthesize the exact requested text with no style tokens. Only the second generation reaches playback. Synthetic anchors are cached only in process memory (at most four, twelve seconds each, five-minute TTL); temporary WAVs are removed with the request. Uploaded references bypass anchor redesign and remain the actual conditioning source; deliveryMode, pace and energy are explicitly degraded for reference/continuation mode. This adds preparation latency, but does not change the pinned models or promise a fixed speaker. Both MLX and CUDA use this path; actual host verification is recorded separately from implementation.

MLX-Audio 0.5.3 remains sentence-batch audio generation. The sidecar checks cancellation/deadlines before and after its existing `feat_decoder.sample` calls, restoring that method when generation exits. This prevents cancelled sentences from holding the worker until final PCM; it does not implement incremental decoding or change numerical parameters. Prefill, individual sampling operations and final decode remain non-preemptible intervals and require measured cleanup bounds. CUDA already checks its native streaming yields; this MLX-only hook does not alter that path.

The reference is never persisted as a voice/model by this implementation. Browser/server memory retains it only for the session; the local sidecar creates a private temporary WAV with its real sample rate and removes it when the generator finishes/closes/errors. Clear stops active preview/live playback and releases page-held references; permission withdrawal removes applied references while retaining the unsubmitted draft for explicit reuse. HTTP bodies are capped at 2 MiB (to fit the existing 30-second STT batch); WebSocket messages and sidecar requests are capped at 1 MiB. References remain independently limited to 20 seconds. Do not log payloads, put clips in Git, or claim conditioning guarantees speaker similarity.

Live voice has a 180-second whole-turn bound, a separate 30-second STT budget, and a fresh 45-second synthesis budget per segment capped by the whole-turn deadline. Preview synthesis incrementally uses the same speech-safe segmenter, preserving segment identity in one ordered preview stream with a single aggregate terminal. The browser preview has a 180-second overall budget, at most 45 seconds per segment, and at most 180 seconds of output audio. The preserved original regression still uses its original 60-second total deadline. This avoids passing an entire paragraph as one CUDA model prompt. These remain finite and cancellation still fences old audio. They are not latency or unlimited-length guarantees.

The browser's **Speech / barge-in sensitivity** slider controls pinned Silero V5 speech probability, not RMS. Balanced 50 requires probability 0.6 and 200 ms sustained ordinary onset, or 150 ms for barge-in. At 0 these are 0.8/250/200 ms; at 100 they are 0.4/150/100 ms. The negative threshold is 0.2 lower, pre-roll is 448 ms (including measured short-word model-onset lag), and trailing silence is 800 ms: after ten minutes of negative input the declared natural-pause fixture has a measured 576 ms low-probability gap. An idle-model reset did not remove it. This correctness adjustment does not change barge-in onset or waive latency targets. Browser-native 16 kHz resampling feeds 512 new samples plus the required 64-sample history to ONNX; history is never duplicated in transmitted PCM. Omitting that history independently caused repeated phrases to split or stop qualifying. Synthetic fixture rejection is not proof of physical room/AEC performance.

The HTTP control path is independent of one main-thread model worker. One successor may wait up to five seconds for cleanup, inside its unchanged deadline; overload is rejected. A successful terminal is sent after worker release. Cancellation fences output immediately but cannot preempt a non-yielding model call. Live ingestion retains at most three semantic units; PCM production has at most 64 packets of lookahead (6.4 seconds), transport is paced to 1.5 seconds, and browser scheduled playback is capped at three seconds with a 250 ms initial buffer. MLX 0.5.3 remains sentence-batch, not token-level streaming. The test page retains the latest 100 transcript entries and at most 30 seconds of capture diagnostics.

The adapter may retry a terminal-only busy rejection at most twice, with the original absolute deadline and no retry after PCM/pre-audio. NeMo cancellation/deadline wakes blocked transport readers and detaches the socket; finite committed input remains the browser path. SGLang voice requests use direct-answer decoding only when the runtime's trusted `policy:spoken-v1` marker is present. Typed-text decoding is unchanged. Split SSE records are buffered, premature EOF/generation limits are errors, and abandoned generation closes its transport. No model or production-provider selection changes.

Private diagnostics: `check-browser-capture.mjs` records real browser/VAD capture with a recording-only fixture socket (not full conversation); `check-speech-content.mjs` sends captured PCM to real ASR; `check-noise-corpus.mjs` downloads four explicitly pinned ESC-50 clips only for private noncommercial testing with attribution; `prepare-voice-audition.mjs <profile>` makes shuffled whole/sentence/fragment samples with one fixed synthetic reference and a private audition page. These do not grant perceptual acceptance. The full real transport is exercised by `soak-browser-voice.mjs`.

Verification: `pnpm test`, `pnpm test:browser-surface`, and `python3 scripts/sidecar-http.test.py` (NumPy required for the anchor test). With either updated profile active, `node scripts/check-voice-settings.mjs` exercises description, reference, and continuation using synthesized neutral audio in memory. `node scripts/check-voice-parity.mjs` checks six-sentence output with real ASR, including absence of style/anchor words. `node scripts/check-live-voice.mjs` checks repeated interruption, a long completed reply, and subsequent turns. `node scripts/check-ai5090-voice.mjs` checks remote controls and segmented preview-to-NeMo content independently of inference readiness. These exclude human recordings, perception, training and saved Assistant voice acceptance.
